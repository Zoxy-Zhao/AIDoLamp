# 六轴补充算法示例

当前台灯使用四个运动关节加独立夹爪，入口见 [four-axis-motion.md](four-axis-motion.md)。本页六轴模块为独立数学示例，与主程序四关节加夹爪接口分开。

`src/motion6dof/` 是独立于摄像头、模型权重和串口的六轴软件演示。它使用理想球腕机械臂模型，提供真实可运行的 FK、解析 IK、目标照射姿态与关节轨迹计算；四关节控制程序见 [motion-control.md](motion-control.md)。

本模块提供独立命令行程序，测试范围为 FK/IK、任务姿态与轨迹的数值一致性。

## 模型约定

长度单位为米，角度单位为弧度，采用右手坐标系。基座 Z 轴向上，零位时两段主连杆沿 +X 伸展；正的肩、肘角按绕 +Y 的右手旋转定义。末端光轴为工具坐标系 +Z。

| 关节 | 运动轴 / 作用 | 默认角度范围 |
|------|---------------|--------------|
| J1 | 基座 Z 轴旋转 | −180°～180° |
| J2 | 肩部局部 Y 轴旋转 | −170°～170° |
| J3 | 肘部局部 Y 轴旋转 | −155°～155° |
| J4 | 球腕局部 Z 轴旋转 | −180°～180° |
| J5 | 球腕局部 Y 轴旋转 | −180°～180° |
| J6 | 球腕局部 Z 轴旋转 | −180°～180° |

基座高度 `h=0.08`，大臂 `a=0.24`，小臂 `b=0.24`，光源 TCP 相对腕心沿 +Z 偏移 `d=0.08`。这些参数是算法演示的默认值，可通过配置替换。三个腕轴在同一点相交；这项构型假设是位置与姿态可以解析解耦的前提。

## FK 与解析 IK

定义 `Rz`、`Ry` 为对应轴的基本旋转矩阵，`p_s=[0,0,h]` 为肩部位置。正运动学为：

```text
R03 = Rz(q1) Ry(q2 + q3)
p_w = p_s + Rz(q1) Ry(q2) [a,0,0] + R03 [b,0,0]
R06 = R03 Rz(q4) Ry(q5) Rz(q6)
p_tcp = p_w + d R06[:,2]
```

解析 IK 先由目标 TCP 和朝向求腕心 `p_w = p_tcp - d R06[:,2]`，然后：

1. 枚举基座朝向及其相反方向，对应正、负平面半径。
2. 在肩肘平面使用余弦定理求肘角，枚举正负两个肘部解。
3. 求肩角，再计算剩余腕部旋转 `R36 = R03.T @ R06`。
4. 对 `R36` 进行 Z-Y-Z 分解，枚举两个腕部解；在腕部奇异处结合参考角和限位选取代表解。
5. 为每个角寻找限位内的等价角，执行 FK 回代，同时核对位置与完整旋转矩阵，排除不满足目标的候选。
6. 以与当前六关节角的欧氏距离选择候选解，减少相邻目标之间的关节跳变。

非奇异情况下最多生成八个基座/肘部/腕部分支。基座轴线上的奇异目标以参考基座角及其相反方向作为候选，不声称枚举所有连续奇异解。无解时抛出 `IKError`，不会把不满足目标的裁剪角作为 IK 成功结果。

## 人脸与书本照射

[LampPlanner](../src/motion6dof/tracking.py) 接收已经表达在机械臂基座坐标系中的三维目标。

- **人脸模式**：保持 J1–J3，利用球腕调整光轴，进行降维求解。工作距离由当前腕心位置决定；目标必须位于工具偏移之外。
- **书本模式**：以目标上方指定距离构造 TCP 位置，并令光轴朝向目标，通过六轴 IK 协调位置和照射姿态。
- **越界处理**：`project_workspace` 可将腕心投影到连杆长度决定的球壳，调用者仍需检查 IK。书本模式通过 `allow_projection=True` 显式启用投影，再重新瞄准并验证 IK；重瞄准后的不可达目标仍会被拒绝。投影可能改变要求的工作距离。

该命令行演示使用合成目标，不调用相机标定、目标检测线程或 STM32。若输入来自视觉系统，必须先完成相机坐标到基座坐标的转换。

## 关节空间插值

对六个关节同步采用五次多项式：

```text
u = t / T, 0 <= u <= 1
s(u) = 10u³ - 15u⁴ + 6u⁵
q(t) = q_start + s(u) (q_goal - q_start)
```

轨迹包含时间戳、关节位置、速度和加速度。端点速度和加速度均为零，适用于从静止开始、静止结束的点到点运动。插值不跨越角度边界取捷径，因此限位内的起终点对应的整段轨迹也在限位内。

可设置统一或逐关节速度上限；利用 `max(ds/du)=1.875` 延长总时长，满足整段连续轨迹的速度上限。`steps` 控制采样数，`duration` 控制请求时长，速度上限可能进一步延长实际规划时长。当前未实现运动中重规划、碰撞检测、动力学约束或硬件执行。

## 运行与复核

在仓库根目录运行，基础算法仅依赖 NumPy：

```bash
python -m pip install numpy
python -m src.motion6dof
python -m src.motion6dof --output output/six-axis-demo.json
python -m unittest discover -s tests -v
```

绘图为可选功能：

```bash
python -m pip install matplotlib
python -m src.motion6dof --plot docs/six-axis-demo.png
```

演示输入为两个书本目标和两个人脸目标；输出包含目标、六关节角、FK 数值残差及带时间戳的轨迹。JSON 显式标记为合成目标演示，`hardware_validated=false` 表示该命令行程序不执行硬件验证。

![六轴姿态与关节轨迹计算结果](six-axis-demo.png)

测试覆盖已知 FK 位姿、250 组固定随机种子的 FK/IK 往返、多个 IK 分支、腕部奇异位姿、基座轴线、完全伸展、关节限位拒绝、工作空间投影、插值端点及速度上限，以及两种照射任务。数值残差表示同一数学模型内的计算一致性，不能解释为实物定位精度。
